= S2T (Speech-to-Text)

== What This Project Is
S2T is a desktop speech-to-text stack for Linux.
It lets you hold a hotkey, speak, and insert recognized text into the focused app.
The project is intended for daily dictation workflows where latency and reliability matter.

== Why It Exists
This repository provides:

* reproducible install and uninstall via Ansible
* cloud-first recognition (Google/OpenAI)
* local fallback (whisper-server / whisper-cli) when cloud fails
* persistent whisper model in memory for faster local fallback
* systemd user services with cgroup limits and log rotation controls

== Architecture
Main components:

* `s2t-monitor.service`: listens for key events and starts/stops recording
* `s2t-whisper.service`: runs `whisper-server` and keeps model loaded
* `s2t-rabbitmq.service` (Podman): durable queue broker for dataset jobs
* `s2t-rabbitmq-drain.service`: consumes RabbitMQ jobs and materializes local `.job` files
* `s2t-dataset-etl.service`: watches correction queue and rebuilds JSONL dataset
* `s2t-codex-bridge.service`: maps corrected Codex chat text to latest pending audio
* `s2t.target`: parent unit for the full S2T stack
* `s2t-controller`: records audio, calls ASR provider, inserts text, writes logs

== Quick Start
. Requirements:
* `ansible-playbook`
* `nix`
* rootless Podman uidmap helpers (`newuidmap`/`newgidmap`, playbook installs on supported Linux families)

. Warm up sudo:
----
sudo -v
----

. Install:
----
make install
----

== Dataset Post-processing
The repository includes an asynchronous post-processing pipeline.

Collection flow:

1. Speak and get transcript in the target app (normal S2T flow).
2. Manually correct the transcript.
3. Submit the corrected text (not raw model output):
+
----
echo "your corrected text" | s2t-controller submit-correction
----
If you work through Codex chat, `s2t-codex-bridge.service` can auto-submit corrected user messages to `submit-correction` when a fresh pending sample exists in the configured window.
4. If speech was split into multiple short recordings (pause/resume), one `submit-correction` maps the text to the latest contiguous pending audio cluster.
5. `s2t-dataset-etl.service` consumes queue jobs and rebuilds dataset JSONL asynchronously.
6. Before ETL, each pair is validated (file checks + optional ASR probe + optional LLM gate via `codex exec`).

Build/transformation pipeline:

* Script: `scripts/build_dataset.py`
* Input: paired files under one root (`*.wav` + `*.txt` with the same relative stem)
* Audio transform: ffmpeg re-encode to 16kHz, mono, 16-bit PCM WAV
* Text transform: control-char cleanup + whitespace normalization
* Output schema (JSONL): `{"audio":"path","sentence":"text"}`
* Split: deterministic `train/test` partition using `--test-ratio` and `--seed`

Output files in the target directory:

* `all.jsonl`
* `train.jsonl`
* `test.jsonl`
* `errors.jsonl`
* `summary.json`

== ASR Behavior
* Cloud-first: set `S2T_ASR_PROVIDER` to `google`/`openai`/`google-v2`
* Local fallback enabled: `S2T_NETWORK_ONLY=0`
* Strict cloud-only mode: `S2T_NETWORK_ONLY=1`

== Troubleshooting
If install fails on sudo in non-interactive mode:

. Run:
----
sudo -v
----
. Run install again:
----
make install
----

If cloud ASR is slow or unavailable:

. Check runtime log for provider timing and fallback path.
. Verify provider keys/credentials in secrets file.
. Set `S2T_NETWORK_ONLY` to match expected behavior.
